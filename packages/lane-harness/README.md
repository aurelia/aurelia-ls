# @aurelia-ls/lane-harness

LSP-boundary lane tests (the medium-volume second layer of the three-layer IDE campaign). Semantic conformance owns
high-volume semantic-runtime query/locus truth; extension-host E2E owns low-volume VS Code state behavior; fixture
verification supports all three by checking reopened pressure-corpus product facts. This harness boots the real language server
(`packages/language-server/out/main.js`) over stdio against a fixture workspace, drives standard
LSP requests (rename, references, hover, completions, definition, documentHighlight, diagnostics, codeAction), applies the results to
in-memory copies of the fixture, and snapshots before/after. The `codeAction` lane resolves lazy actions through
`codeAction/resolve` before validating and applying their versioned edits, matching the editor lifecycle.
A disk-equal `didOpen` is a lifecycle no-op; each following probe request on the same connection is the
readiness/currentness boundary for the synchronized editor overlay.

The diagnostics lane uses only standard `textDocument/diagnostic` pull requests with the server's `aurelia` provider
identifier. It requires an initial full report with a non-empty `resultId`, then proves unchanged reuse with the exact
same opaque ID. Snapshots record only ID presence and the equality relation, never the nondeterministic ID value. They
retain exact ranges, source/code/severity, related information, and normalized diagnostic `data`. Protocol errors,
cancellation, malformed report envelopes, missing IDs, and invalid reuse fail closed. The `codeAction` lane obtains its context
from the same pull path and sends the exact intersecting diagnostics; it never substitutes an empty context after a
failed, unchanged, or malformed initial pull.

Add a lane probe when protocol projection, paging/draining, source mapping, refusal conversion, or `WorkspaceEdit`
assembly is itself under question. Do not mirror the semantic matrix case-for-case. Stateful client behavior such as
dirty buffers, undo/redo, and diagnostics recovery belongs in extension-host E2E.

Layout:

- `probes/<fixture-name>.probes.json` — sidecar probe files (one per fixture, lane-tagged).
  Never place markers inside fixture files; fixtures are owned by semantic-runtime.
- `snapshots/<fixture-name>/<lane>.snap.md` — observed-behavior snapshots, git-diff-reviewable.
  These are generated by the runner; do not hand-edit them. Regenerate with `--update` and
  review the git diff. `verdict`/`reason` in the probe file record operator judgment; a
  `wrong` verdict is a finding, not a work item. Do not combine `--probe` with `--update`:
  a selected-probe run renders only that probe and would truncate the fixture's shared lane snapshot.
- `scripts/run-lane.mjs` — the runner (Slice 1 builds this).

Run (after a workspace build):

```
pnpm --filter @aurelia-ls/lane-harness run lane -- --fixture app-pattern-routed-catalog-storefront --lane rename --update
```

Supported lanes in detection mode:

- `rename`
- `references`
- `hover`
- `completions`
- `definition`
- `documentHighlight`
- `diagnostics`
- `codeAction`
