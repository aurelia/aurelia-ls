# @aurelia-ls/lane-harness

LSP-boundary lane tests (Tier 2 of the IDE testing shape). Boots the real language server
(`packages/language-server/out/main.js`) over stdio against a fixture workspace, drives standard
LSP requests (rename, references, hover, completions, definition, documentHighlight, diagnostics), applies the results to
in-memory copies of the fixture, and snapshots before/after.

**Authority for vision, doctrine, decisions, and Slice 1 scope: `.temp/ide-lane-harness-vision-2026-07-03.md`.**
Read it fully before writing any code here.

Layout:

- `probes/<fixture-name>.probes.json` — sidecar probe files (one per fixture, lane-tagged).
  Never place markers inside fixture files; fixtures are owned by semantic-runtime.
- `snapshots/<fixture-name>/<lane>.snap.md` — observed-behavior snapshots, git-diff-reviewable.
  These are generated by the runner; do not hand-edit them. Regenerate with `--update` and
  review the git diff. `verdict`/`reason` in the probe file record operator judgment; a
  `wrong` verdict is a finding, not a work item.
- `scripts/run-lane.mjs` — the runner (Slice 1 builds this).

Run (after a workspace build):

```
pnpm --filter @aurelia-ls/lane-harness lane -- --fixture app-pattern-routed-catalog-storefront --lane rename --update
```

Supported lanes in detection mode:

- `rename`
- `references`
- `hover`
- `completions`
- `definition`
- `documentHighlight`
- `diagnostics`
